# Crucible Engine

A C++23 / Vulkan 1.3 game engine and editor, built by **Team Medium-Well** for DigiPen's GAM300.
The engine is being developed alongside its game, **Lithomachia**, a co-op horde shooter.

> **Platform:** Windows x64 only (Visual Studio 2022 + Vulkan).

---

## Features

| Area | What's in it |
|---|---|
| **Core / ECS** | Archetype-based ECS, RTTR-driven reflection, JSON scene and prefab serialization, worker-thread pool |
| **Rendering** | Vulkan 1.3 renderer with Slang shaders and VMA. Passes for shadows, SSAO, bloom, tonemapping, volumetric fog, water, particles, toon outlines, world-space UI and debug lines |
| **Animation** | Skinned/animated models, Animator Controller state machines, modular animation, model sockets and attachments |
| **Physics** | Jolt Physics: rigid bodies, character controllers, joints, collision layers, raycasts and queries, contact events |
| **AI & Navigation** | Behaviour Graphs and State Graphs (with node editors), blackboards, flow-field navigation over nav grids and heightfield terrain |
| **Scripting** | Embedded Mono (C# 7.2): scripts compile into `Crucible.Scripts.dll` and attach to entities as components, with Unity-style lifecycle callbacks |
| **Audio** | FMOD Core: buses, clips, 3D audio sources |
| **Networking** | Host/client LAN multiplayer (up to 4 players) over GameNetworkingSockets: snapshot replication, per-component network policies, networked prefabs and scene objects |
| **UI & Text** | Screen-space and world-space UI, MSDF font rendering (msdfgen / msdf-atlas-gen) |
| **Diagnostics** | Custom logger with sinks and levels, scoped timers / profiling, fatal-error handling |
| **Editor** | Dear ImGui + ImGuizmo editor with Unity-style panels: Hierarchy, Inspector, Scene and Game views, Asset Browser, Console, Animator, Behaviour Graph and State Graph editors, Network panel, texture and font importers, undo/redo, play/pause, one-click **Package Game** |
| **Asset pipeline** | Offline Model Compiler, Texture Compiler (Compressonator) and a **Cook** tool that turns `Assets/` into runtime-ready `Resources/` |

---

## Requirements

- **Windows 10/11, x64**
- **Visual Studio 2022** with the *Desktop development with C++* workload
- **[Vulkan SDK](https://vulkan.lunarg.com/)** (1.3 or newer) installed system-wide. It also provides `slangc`, which the build uses to compile shaders.
- **CMake 3.23.1+** (optional: `run.bat` downloads a local copy of CMake 3.30.3 if none is found on your `PATH`)

All other dependencies, including the Mono SDK, are already in `Extern/`. You don't need to install anything else.

## Getting started

```bat
git clone https://github.com/kwan-c/csd3401f26_Team_MediumWell.git
cd "csd3401f26_Team_MediumWell\Project\Crucible Engine"
run.bat
```

1. `run.bat` configures the project with CMake into `Build/`.
2. Open **`Build/Crucible.sln`** in Visual Studio 2022.
3. **Editor** is the startup project. Build and run it (F5) to launch the editor.
4. To run the standalone game instead, set **Game** as the startup project. It builds as `Lithomachia.exe`.

| Script | What it does |
|---|---|
| `run.bat` | Generates the Visual Studio solution in `Build/` |
| `clean.bat` | Deletes `Build/` and any local CMake copy |
| `rebuild.bat` | `clean.bat` followed by `run.bat` |

### Packaging a release build

Do it from the editor with **File > Package Game**, or from the command line:

```bat
cmake --build Build --config Release --target Game Cook
cmake --build Build --config Release --target PACKAGE
```

This produces `Build/Lithomachia-<version>-win64.zip`. Players unzip it and run `Lithomachia.exe`.

## Repository layout

```
Project/Crucible Engine/
├── Engine/          Core engine library (ECS, rendering, physics, audio, AI, networking, scripting host, ...)
├── Editor/          ImGui-based editor (panels, graph editors, undo, importers, packaging)
├── Game/            Game executable (Lithomachia)
├── ManagedScripts/  C# runtime API (Transform, RigidBody, Input, Physics, ...) and script templates
├── Assets/          Source assets: scenes, prefabs, models, textures, audio, scripts, graphs
├── Resources/       Cooked / compiled runtime assets (generated by Cook)
├── Tools/           Model and texture compilers, Cook, packaging, Mono and script helper scripts
├── Docs/            Subsystem documentation (animation, scripting, model import)
└── Extern/          Third-party libraries
```

## Scripting quick start

Create a script from the editor with **Inspector > Add Component > Create C# script "Name"**, or from the engine root run:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Tools\NewScript.ps1 -Name MyScript -Entity
```

Any `.cs` file under `Assets/Scripts/` is picked up automatically the next time you build. The C# API lives in `ManagedScripts/Runtime/`.
